# Runner images

- This is public source. Use synthetic examples; keep private candidate inventories, company infrastructure details and credentials out of commits/artifacts.
- Collect from actual machines. Published tool lists are expected configuration, not proof of installed tools.
- `uv run python scripts/check.py` is the static gate. `uv run python scripts/test.py` adds behavioral and branch-coverage checks. Run `actionlint` after workflow changes.
- Public PR workflows use GitHub-hosted runners only. Keep private fleet inventories in their owning repositories; public recipe builds run locally without a registered host runner.
- Hosted reference snapshots are intentionally versioned under `snapshots/github-hosted/`, per the requested Git history contract. Artifacts transfer observations between jobs; Git is the durable reference. Commit only changed observations. Changes to the JSON schema must preserve consumers or use a new schema version.
- Successful public-recipe builds may append immutable bundles under `qualifications/tart/`. Failed comparison or image-identity checks never issue passing records. The issue command owns an isolated local checkout; release publication is main-only and manually dispatched by that command. PRs use hosted runners only.
- Rebuild reminders have a stable bot-only marker per profile. All issue mutations share the `image-rebuild-issues` concurrency queue. Include the executable one-command bootstrap in each reminder. Close only from a published, asset-verified GitHub Release recorded in Git for the current build-input fingerprint; local qualification, GHCR publication or artifact upload alone is insufficient. Keep older uploads as evidence when current inputs change.
- The local command reuses gh authentication, journals completed stages and reconnects to an existing release workflow on replay. Preserve failed owned records under artifacts/recovery; never clean a developer checkout. A fleet image may change only through an explicitly registered host-local after-release consumer; the public factory has no fleet details. Signed provenance must identify the actual local builder and distinguish hosted validation from building.
- Cloud publication is intentionally automatic from trusted main events and requires no rebuild issues. Isolate its fingerprint from macOS. Base profiles qualify provisioning smoke only; attach parity differences without claiming complete hosted equivalence. Require source/ownership read-back, signed evidence, security checks and verified release assets. Cleanup may delete only this build's owned resources and must preserve any image referenced by a published release. Never place real destination IDs in public fixtures.

- Accepted legacy-runtime risks are documented in `security-exceptions.md`; preserve exact advisory/name/version/type/location scope and scanner `ignoredMatches` reasons. Run `uv run python scripts/check-runner-security.py` after policy changes. Other High/Critical findings remain blocking.
- Supplier-fixed Ubuntu kernel dispositions for the cloud images are documented in `cloud/security-dispositions.md`; `cloud/kernel-fixes.json`, the `cloud/grype.json` kernel rules and the native `cloud/linux/verify-kernel.py` binding stay mechanically coupled — run `python3 cloud/check-kernel-security.py` with Grype after changes. They are not risk acceptances; unreleased-fix, not-affected and unknown tracker cases stay blocking, and absent bound kernels never waive newer kernels. Azure gallery image versions are created excluded-from-latest; consumers use exact receipt image IDs.
- Android Bouncy Castle refresh/independent verification and its native consumer boundary are documented in `macos/android-bc-security.md`. Preserve official JAR checksums, classpath integrity, rollback and qualification-bound receipts; component validation does not establish a new factory image qualification.
